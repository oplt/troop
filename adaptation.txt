# Repository Improvement Report

Generated from analysis of the Troop repository (FastAPI + React orchestration platform with semantic/episodic memory, RAG, Celery workers, pgvector, and MUI frontend).

Assumption: production runs with Postgres + pgvector, Redis, Celery workers, and `APP_ENV=production`. Verify staging query plans and load tests before high-volume rollout.

---

## Executive Summary

Phase 1, Phase 2 quick wins, and the completed priority fixes have been removed from this report.

Recent completions:
- Approval endpoints moved into a dedicated orchestration router slice.
- RAG retrieval and grounded-answer evals now have a committed gate and CI workflow.
- pgvector HNSW index validation now has a repeatable plan checker.
- RAG answer generation now resolves project-scoped model/provider settings before runtime defaults.
- HTTP exception payloads now share one structured response shape while preserving legacy `detail`.
- Frontend route errors now send route/project tags to Sentry when a browser client is present.
- Deployment, Celery topology, pgvector, rollback, and load-test guidance now live in `docs/DEPLOYMENT_RUNBOOK.md`.

**Highest-impact remaining improvements:**
1. Continue orchestration service/router extraction in small domain PRs.
2. Continue splitting `ProjectDetailView` tab internals.
3. Add cross-encoder reranking only if the eval gate shows a precision gap.

## Remaining Priority Improvements

### 1. Continue orchestration service/router extraction
- **Category:** Backend architecture
- **Severity:** High
- **Effort:** Large
- **Risk:** Medium
- **Status:** Partial
- **Current state:** Domain deps exist in `api/deps/orchestration.py` and `api/deps/rag.py`; execution, approvals, memory, GitHub sync, knowledge, evals, and brainstorm facades exist. Approval endpoints are extracted to `backend/modules/orchestration/routers/approvals.py`. The legacy router still owns several broad domains.
- **Recommendation:** Continue extracting narrow route/service slices for provider config, brainstorm, project documents, memory, GitHub sync, and task execution while preserving API contracts.
- **Expected benefit:** Better test isolation, clearer ownership, and lower regression risk during feature work.

### 2. Split `ProjectDetailView` tab internals
- **Category:** Frontend architecture
- **Severity:** High
- **Effort:** Large
- **Risk:** Medium
- **Status:** Partial
- **Current state:** `OrchestrationProjectDetailPage.tsx` is now a thin lazy route shell, but `frontend/src/pages/projectDetail/OrchestrationProjectDetailView.tsx` still contains too many tab views and behaviors.
- **Recommendation:** Extract each major tab into colocated modules and hooks before adding new project-detail behavior.
- **Expected benefit:** Smaller review surface, safer UI changes, and easier project-detail smoke tests.

### 3. Add cross-encoder reranking only after quality metrics justify it
- **Category:** AI quality / cost control
- **Severity:** Medium
- **Effort:** Medium
- **Risk:** Medium
- **Status:** Deferred
- **Current state:** Keyword boost reranking and RAG eval gates exist. Cross-encoder reranking is not implemented.
- **Recommendation:** Use retrieval eval results to decide whether a cross-encoder is worth added latency/cost. If justified, add it behind `RAG_RERANK_ENABLED` with timeout, max candidate caps, and telemetry.
- **Expected benefit:** Better precision for ambiguous queries without adding unmeasured cost.

## Final Recommendations

**Do next:**
- Continue backend orchestration router extraction by domain, next with providers, brainstorm, or project document routes.
- Continue extracting `ProjectDetailView` tab internals into smaller views/hooks.
- Run the pgvector plan checker in staging with 10k+ chunks per representative project.
- Add project-detail smoke tests after tab extraction.

**Defer until metrics justify:**
- Cross-encoder reranking.
- Unified knowledge model across AI Studio and project docs.
- Score-based context trimming beyond configured token budgets.
- Full orchestration DI rewrite beyond incremental domain extraction.

**Verify before release:**
- Run `pnpm build && pnpm exec tsc --noEmit`.
- Run backend tests plus `backend.tools.rag_eval_gate`.
- Run `backend.tools.pgvector_plan_check` against staging data.
- Load test pooled connections under concurrent run + ingest load.
