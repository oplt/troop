# orchestration/service.py Decomposition Plan

Source: `backend/modules/orchestration/service.py` (13,762 lines, class `OrchestrationService`).
Goal: shrink to thin facade (<2k lines) that composes domain services.

Strategy: split `OrchestrationService` into focused services by domain. Move method
groups verbatim (keep signatures) to new files. `OrchestrationService` keeps only
cross-cutting glue (run execution routing, shared helpers) or becomes a facade that
delegates. Shared `self.db`, `self.repository`, `self.audit`, etc. → pass via
constructor to each sub-service.

## Cross-cutting strategies

1. **Facade pattern.** Keep `OrchestrationService` as thin composition root —
   instantiate sub-services in `__init__`, expose same public method names that
   proxy to sub-services. Router stays unchanged during migration.

2. **Mixins (interim).** If splitting to separate classes is too disruptive,
   split by `*Mixin` classes in separate files (e.g. `_agents_mixin.py`,
   `_github_mixin.py`), compose into `OrchestrationService`. Keeps `self.db`
   access intact. Move later once imports settle.

3. **Repository layer.** Many methods do direct SQLAlchemy queries. Push to
   per-module `repository.py` files. `projects/orchestration_repository.py`
   and `memory/repository.py` already exist — extend them.

4. **Pure helpers → module level.** Methods not using `self` (e.g.
   `_acceptance_criteria_items`, `_acceptance_item_matches_output`,
   `_brainstorm_first_line`, `_slugify`, `_message_similarity`,
   `_jsonify`, `_normalize_*`) → plain functions in `_utils.py`. Reduces class
   size, eases testing.

5. **Constants/enums → schemas.** `TASK_TRANSITIONS`, `EXTERNAL_LINK_KINDS`,
   `DEFAULT_PORTFOLIO_EXECUTION_POLICY`, `OPENAI_FAMILY_PROVIDER_TYPES`,
   `GITHUB_WEBHOOK_EVENT_ALLOWLIST` → move next to consumers (schemas.py files).

6. **Prompt assembly → dedicated `prompt_builder.py`.** Lines 11337–11725
   (company brief, preferences, memory context, scratchpad, context packet,
   task prompt) compose prompts. Isolate in `orchestration/prompt_builder.py` →
   easier to unit-test prompt shape.

7. **Workflow/durable exec → already in `execution_workflow.py`.** Leaker
   methods (`_mark_run_step`, `_ensure_run_workflow`, `_durable_workflow_payload`,
   etc.) can move into `execution_workflow.py` as module-level functions
   accepting a run.

8. **Webhook handlers → dispatcher map.** 12 `_process_webhook_*` methods can
   flatten into dict `{event_name: handler_fn}`. Shrinks branch tree in
   `process_github_webhook_sync_event`.

9. **Split execute_* run variants.** `_execute_single_agent_run`,
   `_execute_manager_worker_run`, `_execute_review_run`,
   `_execute_brainstorm_run`, `_execute_debate_run` →
   `orchestration/executors/{single,manager,review,brainstorm,debate}.py`.
   Each executor becomes a class with one `run()` method.

10. **Background jobs → `orchestration/jobs.py`.** Long-running workers
    (`process_memory_ingest_jobs_worker`, `run_episodic_retention_and_archive_job`,
    `sweep_expired_memory_globally`, `poll_stale_github_issue_links`,
    `run_provider_health_checks`, `run_global_sla_escalation_scan`,
    `run_memory_compaction_backfill`, `process_episodic_index_embedding_batch`,
    `backfill_episodic_search_index`, `run_orchestration_job`) → dedicated jobs
    module invoked by scheduler. Decouples from request-path service.

11. **DI over shared `self`.** Sub-services take `db`, `repository`,
    `audit`, `notifications`, `toolbox`, `provider_registry` via constructor.
    Avoids god-object coupling, enables per-service unit tests.

## Migration order (safest → riskiest)

1. Extract module-level helpers + constants (zero risk).
2. Extract pure staticlike helpers (no `self` usage) to `_utils.py`.
3. Move Agent CRUD to `team/service.py` (isolated, well-bounded).
4. Move Eval/Brainstorm/Approvals (self-contained feature chunks).
5. Move GitHub (webhooks + sync + connections) — large but isolated.
6. Move Memory pipeline (touches many callers — add facade wrappers first).
7. Move Projects + Tasks.
8. Move Providers.
9. Split Execution into executors + routing + core.
10. Collapse remaining OrchestrationService to facade.

Each step: keep public method on `OrchestrationService` as thin delegate; update
router imports last.
